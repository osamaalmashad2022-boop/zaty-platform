## ٢. استراتيجية الاستضافة: Cloudflare R2 مقابل الاستضافة المباشرة

لضمان أعلى درجات الأداء والموثوقية وتخفيض التكاليف التشغيلية إلى الصفر، تم تحليل خياري الاستضافة التاليين:

### أ) مقارنة معمارية مفصلة

| وجه المقارنة | الاستضافة الثابتة المباشرة (Cloudflare Pages) | التخزين السحابي الكائني (Cloudflare R2 Storage) |
| :--- | :--- | :--- |
| **آلية العمل** | رفع ملفات `public/media/` مباشرة ضمن حزمة البناء عبر مستودع Git و Pages deployment. | رفع الملفات إلى Bucket مخصص على R2 وربطها بنطاق فرعي مثل `media.zaty.app`. |
| **تكلفة التخزين (Storage Cost)** | **مجانية تمامًا** ضمن حصة الحزمة الإجمالية في حساب Cloudflare Pages المجاني. | **10 GB مجانية شهريًا** (تكفي لأكثر من 115 ملفًا إضافيًا من نفس النوع). |
| **تكلفة نقل البيانات (Egress Bandwidth)** | مجانية وغير محدودة لمستخدمي Cloudflare Pages العاديين. | **صفر دولار ($0 Egress Fees)**؛ ميزة R2 الفريدة بعدم فرض أي رسوم على باندويث التنزيل. |
| **قيود الحجم الأقصى** | الحد الأقصى للملف الواحد هو **25 MB** (أكبر ملف لدينا 12.39 MB فقط؛ آمن تمامًا). | يدعم ملفات ضخمة تصل لعدة تيرابايت دون قيود. |
| **سرعة دورة البناء (Build Duration)** | يرفع 86 MB مع البناء، مما قد يستهلك 30–60 ثانية إضافية في كل رفع للمستودع. | بناء فائق السرعة لأن المستودع البرمجي يبقى خفيفًا وخاليًا من ملفات الوسائط الكبيرة. |
| **التحكم بالنسخ والتحديث** | تحديث الملف يتطلب commit و push وإعادة بناء الحزمة بالكامل. | تحديث أو استبدال فوري للملف بـ API أو Dashboard دون إعادة بناء المنصة. |

### ب) القرار المعماري المعتمد لمراحل الإطلاق
1. **المرحلة الحالية (MVP Launch · 86.20 MB):**
   * اعتماد **الاستضافة الثابتة المباشرة في `public/media/`**؛ حيث يقع الحجم الإجمالي (86.20 MB) ضمن النطاق المقبول والمريح لحدود Cloudflare Pages، كما تقع كافة الملفات الـ 16 تحت سقف الـ 25 MB. هذا الخيار يُلغي تعقيدات إعداد الدومينات الفرعية ومفاتيح S3 API ويضمن الجاهزية الفورية بنقرة واحدة.
2. **المرحلة المستقبلية (Scale & Phase 3 Expansion):**
   * نقل الأصول إلى **Cloudflare R2 Bucket** عند إضافة وسائط الفصل الدراسي الثاني والوحدات الإثرائية وتجاوز حاجز الـ 250 MB، مع توجيه طلبات `/media/*` عبر Cloudflare Worker أو Custom Domain لتحقيق أقصى سرعة استجابة واستغلال الـ 10 GB المجانية بصفر تكاليف باندويث.

## ٣. قواعد التخزين المؤقت في Service Worker (`public/sw.js`)

تعتمد منصة «ذاتي» استراتيجية PWA متقدمة للتخزين المؤقت وإدارة البيانات على شبكات المحمول المصرية محدودة الباقة:

### أ) التخزين عند الطلب (Cache-on-Demand) وعدم التحميل المسبق التلقائي
* **القاعدة:** ملفات الوسائط الثقيلة (`.mp4`, `.mp3`) **لا تُحمَّل مطلقًا** أثناء تثبيت تطبيق الويب (SW `install` event).
* **السبب التربوي والتقني:** حماية باقات إنترنت المتعلمين؛ إذ أن تنزيل 86 MB فور فتح الموقع قد يستنزف باقة هاتف المتعلم دون رغبته.
* **التنفيذ:**
  ```javascript
  // في public/sw.js
  const MEDIA_CACHE = 'ict-prep3-media-v2';
  
  function isMediaAsset(pathname) {
    return /\.(mp4|webm|mp3|wav|ogg|m4a|vtt)$/i.test(pathname);
  }
  ```

---

### ب) دعم طلبات النطاق الجزئي RFC 7233 (HTTP 206 Partial Content)
* **المشكلة:** متصفحات Safari على iOS و Chrome ترفض تشغيل مقاطع الفيديو والصوت من الـ Cache Storage في وضع الأوفلاين إذا لم يستجب الـ Service Worker لترويسة `Range: bytes=start-end`، مما يتسبب في شاشة سوداء وتعطل شريط التقديم والترجيع (Scrubber Seeking).
* **الحل المعتمد في المنصة:**
  يقوم `sw.js` باعتراض طلبات الوسائط، وقراءة مصفوفة البايتات الكاملة من `Cache.match()`، واقتطاع النطاق المطلوب بدقة عبر `ArrayBuffer.slice()`، وإرجاع استجابة HTTP معيارية برمز **`206 Partial Content`** وترويسات:
  - `Content-Range: bytes start-end/total`
  - `Content-Length: chunkLength`
  - `Content-Type: video/mp4` أو `audio/mpeg`
  - `Accept-Ranges: bytes`
  مما يسمح للمتعلم بتقديم وتأخير الفيديو والصوت بسلاسة تامة حتى أثناء انقطاع الإنترنت الكامل.

---

### ج) التنزيل عند الطلب لكل محطة (On-Demand Station Pre-caching)
* تتيح المنصة زرًا اختياريًا في واجهة كل محطة: **«تحميل وسائط المحطة للعمل أوفلاين»**.
* عند النقر، تُرسل الواجهة رسالة موجهة إلى الـ Service Worker:
  ```javascript
  navigator.serviceWorker.controller.postMessage({
    type: 'CACHE_STATION_MEDIA',
    urls: [
      '/media/video-2-1.mp4',
      '/media/podcast-2-4.mp3',
      '/media/caption-2-1.vtt',
      '/media/caption-2-4.vtt'
    ]
  });
  ```
* يقوم الـ Service Worker بفتح `MEDIA_CACHE` وتنزيل وحفظ ملفات تلك المحطة المحددة فقط دون المساس بباقي المحطات.

---

### د) إدارة الذاكرة وتجديد الإصدارات (Cache Invalidation)
* يتم تمييز إصدار الوسائط عبر المعرّف `ict-prep3-media-v2`.
* في حدث التفعيل `activate`، يقوم الـ Service Worker بفحص كافة الكاشات الموجودة على جهاز المتعلم، وحذف أي كاش قديم لا ينتمي لقائمة الكاشات المعتمدة الثلاثة:
  - `ict-prep3-shell-v2` (هيكل المنصة ومحرك Skulpt بايثون أوفلاين)
  - `ict-prep3-pages-v3` (صفحات الدروس والامتحانات الثابتة)
  - `ict-prep3-media-v2` (وسائط الفيديو والصوت المعتمدة)
  مما يضمن عدم تراكم ملفات مهملة على ذاكرة هاتف المتعلم.
